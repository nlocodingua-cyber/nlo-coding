# Гарячі клавіші — переносний модуль

`Cmd+Z` скасувати · `Cmd+Shift+Z` повернути · `Ctrl+Y` повернути · `Cmd+C` / `Cmd+V` копіювати й вставити об'єкт.

Тека `lib/keys/` нічого не знає про конкретний сервіс: ні про таблиці, ні про серверні дії, ні про дизайн-систему. Залежність одна — React. Тому переноситься копіюванням теки.

## Три файли

| Файл | Що робить |
|---|---|
| `history.ts` | стек кроків у пам'яті вкладки; кожен крок знає, як себе відкотити й повторити |
| `clipboard.ts` | копіювання об'єктів (не тексту) через системний буфер |
| `KeyboardShortcuts.tsx` | єдиний слухач клавіш + тост; зшиває обидва |

## Перенести в інший сервіс — три кроки

**1.** Скопіювати теку `lib/keys/` як є.

**2.** Поставити компонент один раз, високо в дереві (layout):

```tsx
<KeyboardShortcuts
  серверНазад={...}     // не обов'язково
  серверВперед={...}    // не обов'язково
  щоКопіювати={...}     // не обов'язково
  кудиВставити={...}    // не обов'язково
/>
```

Без жодного крюка воно вже працює — скасовує те, що екрани записали в історію.

**3.** У місцях, де щось міняється, записати крок:

```ts
запамʼятати({
  опис: "Пересунуто крок",
  вперед: () => зберегти(нове),
  назад: () => зберегти(старе),
  злити: `${id}:позиція`,   // тридцять кадрів перетягування = один крок історії
});
```

Головне правило: `вперед` **не викликається** під час запису. Дію людина вже зробила — повторний виклик подвоїв би її.

## Два рівні пам'яті

Клієнтський стек знає все, що людина зробила у вкладці, включно з дрібницею. Серверний журнал (якщо він у сервісі є) — глибша пам'ять, переживає перезавантаження сторінки.

Порядок такий: спершу свій стек, і лише коли він порожній — `серверНазад`. Так дрібні жести відкочуються миттєво, а вчорашні зміни все одно доступні.

Чому не лише сервер: журнали навмисно не пишуть координати вузлів і подібне — інакше стрічка змін тоне в сотнях подій, поки людина возить мишею. А відкотити перетягування хочеться саме одразу.

## Чого модуль навмисно не робить

- **Не чіпає поля вводу.** Поки курсор у полі, `Cmd+Z` скасовує набраний текст, `Cmd+C` копіює символи. Перехопити — зламати звичку, старшу за будь-який наш інтерфейс.
- **Не краде виділений текст.** Є виділення на сторінці — `Cmd+C` віддається браузеру.
- **Не робить кілька кроків одночасно.** Затиснутий `Cmd+Z` інакше шле десяток запитів, які повертаються в довільному порядку.

## Копіювання об'єктів

У системний буфер лягає людський текст, а сам об'єкт їде причепленим рядком-міткою. Тому вставка в чат чи пошту дає читабельне, а вставка у свій інтерфейс — повноцінний об'єкт.

```ts
щоКопіювати={() => виділене && {
  вид: "process-step",
  звідки: block.key,
  дані: виділене.data,
  підпис: виділене.title,
}}

кудиВставити={async (н) => {
  if (н.вид !== "process-step") return null;   // null = «сюди це не вставляється»
  await створитиКрок(н.дані);
  return `Вставлено: ${н.підпис}`;
}}
```

## Стан у NLO System

Підключено в `app/b/[biz]/layout.tsx` через `components/UndoHotkeys.tsx`.

В історію пишуть:
- полотно процесів — переміщення кроку, зміна розміру, правка полів кроку (через єдину точку `persist`);
- стрілки — видалення і підпис гілки, з поверненням тих самих боків.

Глибший рівень — журнал `config_events` (`lib/undo.ts` + `app/undo-actions.ts`): правки записів, подань, баз, колонок, налаштувань простору.

Ще не покрито: створення й перецілювання стрілки, повернення видаленого рядка (журнал зберігає лише змінені ключі, а для вставки назад потрібен повний знімок), `Cmd+C` / `Cmd+V` для кроків і рядків сітки — крюки готові, лишилось під'єднати екрани.
